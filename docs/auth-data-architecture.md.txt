Überblick
Dieses Dokument beschreibt den aktuellen technischen Stand der App im Bereich:
	•	Authentifizierung
	•	Datenarchitektur

Ziel ist es, einen klaren Überblick zu geben, wie das System aktuell aufgebaut ist und wie nah es am Publish-Level ist.

1. Architektur (High-Level)
Die App folgt einer local-first Architektur mit minimalem Backend.
Prinzipien:
	•	User-Daten bleiben lokal auf dem Gerät
	•	Firebase wird nur für Identität genutzt
	•	Keine zentrale Datenbank für Produktdaten
	•	Analytics getrennt von Produktlogik

3. Datenarchitektur (Local-First)
Grundprinzip
Alle produktrelevanten Daten werden lokal auf dem Gerät gespeichert.
Gespeicherte Daten:
	•	Onboarding-Antworten
	•	Birthday (Quelle der Wahrheit)
	•	Alter (abgeleitet)
	•	Geschlecht
	•	Cravings
	•	Slips
	•	Progress / Streaks
	•	Settings
Wichtige Entscheidungen:
	•	Birthday → berechnet Age
	•	Keine redundanten Felder
	•	Klare Trennung von Profil / Progress / State

Vorteile
	•	Keine Backend-Abhängigkeit
	•	Datenschutzfreundlich
	•	Schnelle Performance
	•	Offline-first Nutzung möglich

4. Analytics (PostHog)
Setup

Eigenschaften:

Aktuelle Events

Bewertung

	•	Skalierbar
	•	Free-tier freundlich
